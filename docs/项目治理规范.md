# mythos-skills 项目治理规范

> 最后更新: 2026-08-30

## 一、分支策略

| 分支 | 用途 | 保护 |
|------|------|------|
| `main` | 稳定基线 | 禁止 force push，需 PR 合并 |
| `feat/*` | 功能开发 | 合并到 main 需通过质量门禁 |
| `fix/*` | 修复 | 同上 |
| `chore/*` | 工具与基建 | 同上 |
| `docs/*` | 文档 | 同上 |

## 二、分支保护（main）

- 合并前必须通过 PR
- 必须通过质量门禁（测试 + lint）
- 禁止 force push
- 要求线性历史（rebase）
- 禁止直接提交到 main

## 三、质量门禁清单

| 检查项 | 阻塞级别 |
|--------|---------|
| pytest 全部通过 | BLOCK |
| 覆盖率不下降 | BLOCK |
| ESLint/ruff 无错误 | BLOCK |
| 无 TODO/FIXME/HACK 占位符 | BLOCK |
| 无密钥泄露 | BLOCK |
| TypeScript strict 编译通过 | BLOCK |

## 四、文档规范

### 4.1 必须文档

| 文档 | 路径 | 更新时机 |
|------|------|---------|
| 项目宪章 | `CHARTER.md` | 架构变更时 |
| 项目初始化必检清单 | `docs/项目初始化必检清单.md` | 初始化、迁移、接手、恢复任务时 |
| 开发环境手册 | `docs/开发环境手册.md` | 环境变更时 |
| 生产部署手册 | `docs/生产部署手册.md` | 部署流程变更时 |
| 生产基线文档 | `docs/生产基线文档.md` | 每次上线后 |
| 发包与后续开发备忘录 | `docs/备忘录.md` | 每次发包准备、上线完成、后续版本调整时 |
| 配置与测试规范 | `docs/配置与测试规范.md` | 规范变更时 |
| 项目治理规范 | `docs/项目治理规范.md` | 流程变更时 |
| 验证与调试手册 | `docs/验证与调试手册.md` | 调试方法变更时 |
| 栈初始化模板 | `docs/_shared/INIT_TEMPLATE_*.md` | 技术栈或初始化规则变更时 |

### 4.2 文档同步

- 全局规范（`docs/_shared/`）由 sync-engine 自动同步，禁止手动修改
- 项目特有文档如需引用全局规范，使用 `[docs/_shared/XXX.md](./_shared/XXX.md)` 链接
- 新项目初始化时运行 `pwsh sync-engine.ps1 -ProjectPath . -Write -AutoApply`

## 五、版本管理

- 语义化版本: `MAJOR.MINOR.PATCH`
- 每次上线更新 `docs/生产基线文档.md` 的版本链
- 每次发包准备和上线完成同步更新 `docs/备忘录.md` 的阻断项、证据和后续开发池
- Tag 格式: `vMAJOR.MINOR.PATCH`

## 六、红线

> 详见 [docs/_shared/RED_LINES_CATALOG.md](./_shared/RED_LINES_CATALOG.md)

1. 不直接删除文件（移入 `.archive/` 或 `.trash/`）
2. 零密钥入库
3. 容器 runtime offline
4. 未经讨论不新增/升级依赖
5. 先写测试再写码
