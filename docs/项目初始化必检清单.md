# mythos-skills 项目初始化必检清单

> 最后更新: 2026-08-30
> 本文档是新项目接入 AIStandard / Codex Standard 的第一入口。初始化、接手、迁移、恢复任务时必须先核对本清单，再进入实现或测试。

## 0. 快速结论

| 项 | 必填内容 | 当前项目记录 |
|----|----------|--------------|
| 项目身份 | 项目名、使命、主要使用者、仓库路径 | 见 `project-preset.json`、`CHARTER.md`、`README.md` |
| 技术栈 | 主要语言、框架、包管理器、运行方式 | 见 `project-preset.json`、`AGENTS.md`、栈模板 |
| 环境入口 | 本地/容器/生产环境切换方式 | 见 `docs/开发环境手册.md`、`docs/配置与测试规范.md` |
| 配置位置 | `.env*`、配置模块、运行时注入位置 | 见本文第 3 节 |
| 测试入口 | 最小测试、回归测试、E2E、测试禁区 | 见 `TEST_SCENARIOS.md` 与 `scripts/pre_test_safety_check.ps1` |
| Git 入口 | remote、分支、提交边界、推送路线 | 见本文第 8 节 |
| 个人习惯 | 机器级偏好、端口、标准根、IDE 配置 | 见本文第 9 节 |

## 1. 项目身份必检

必须存在并核对:

- `project-preset.json`: 机器可读项目身份，必须声明 `project_name`、`description`、`ides`、`runtime.ports`、`codex.profile`、`sync.source`。
- `AGENTS.md`: AI 执行入口，必须包含测试、文件安全、恢复流程、工作流路由。
- `CLAUDE.md`: Claude Code 入口，若项目启用 Claude Code 必须与 `AGENTS.md` 同步关键约束。
- `README.md`: 人类入口，必须能说明项目用途、启动方式和主要目录。
- `CHARTER.md`: 项目使命、范围、非目标、红线。没有时应创建并标记确认日期。

判定:

- 缺 `project-preset.json` 时，不得声称已接入标准同步。
- 缺 `AGENTS.md` 时，不得开始跨文件实现。
- 项目名、容器名、数据库名、端口和仓库名不一致时，先记录差异，不直接重命名。

## 2. 环境必检

必须记录以下环境:

| 环境 | 必检项 | 证据位置 |
|------|--------|----------|
| 本机开发 | OS、PowerShell、Python/Node/Rust/包管理器版本 | `docs/开发环境手册.md` |
| 容器开发 | Dockerfile、compose、容器名、镜像 tag、挂载、端口 | `Dockerfile`、`docker-compose*.yml`、`docs/_shared/DOCKER_IRON_LAWS.md` |
| 测试环境 | ENV/APP_ENV、测试数据库、mock 服务、禁用生产资源 | `scripts/pre_test_safety_check.ps1`、`TEST_SCENARIOS.md` |
| 生产环境 | 生产主机、镜像、部署目录、数据库、回滚方式 | `docs/生产部署手册.md`、`docs/生产基线文档.md` |

环境红线:

- 测试命令不得在 `ENV=production` / `APP_ENV=production` 下运行。
- 容器化项目后端测试默认在容器内执行，宿主机测试必须有项目文档明确允许。
- 生产数据库、生产密钥、真实第三方写接口不得作为测试默认值。

## 3. 配置与敏感信息必检

初始化时必须定位并分类:

| 类型 | 常见位置 | 规则 |
|------|----------|------|
| 本地敏感值 | `.env`、用户级环境变量、容器 runtime 注入 | 不入库 |
| 示例配置 | `.env.example`、`.env.dev`、`.env.prod.example` | 可入库但不得含真密钥 |
| 应用配置 | `settings.py`、`config.py`、`config.toml`、`application.yml` | 必须说明环境切换逻辑 |
| AIStandard 个人偏好 | `codex_standard/personal.json`、`personal.json.example` | 禁止密钥，只放偏好和机器覆盖 |
| 端口注册 | `codex_standard/port-registry.json`、`project-preset.json.runtime.ports` | 同机唯一 |

必须核对:

- 配置加载顺序: 默认值 -> 环境变量 -> 本地文件 -> runtime 注入。
- 敏感字段: token、password、secret、api_key、private key、bearer token。
- 生产保护: 生产配置必须通过显式环境选择，不得被测试默认命中。

## 4. 技术栈模板选择

按项目实际组合读取:

- Python / FastAPI / 后端服务: `docs/_shared/INIT_TEMPLATE_PYTHON_BACKEND.md`
- Node / Vue / React / 前端项目: `docs/_shared/INIT_TEMPLATE_NODE_FRONTEND.md`
- Rust / 系统服务 / 高性能采集: `docs/_shared/INIT_TEMPLATE_RUST_SYSTEM.md`
- 文档、技能、规范、研究型项目: `docs/_shared/INIT_TEMPLATE_DOCS_SKILLS.md`
- Docker 项目共同约束: `docs/_shared/DOCKER_IRON_LAWS.md`

多栈项目必须同时满足多个模板；冲突时以更严格的运行安全和测试边界为准。

## 5. 工作流规范必检

必须确认:

- 默认工作流: `fsm-lite`、`fsm-10-stage`、`debugging-workflow`、`fsm-audit-gate` 中的适用规则。
- 审计类任务: 先读文档和当前代码，先证据后结论。
- 实现类任务: 先界定影响面，再改代码，再运行最小必要验证。
- 文档类任务: 更新唯一权威文档，并在 `docs/INDEX.md` 或项目文档入口登记。

初始化时必须写明项目默认路由:

| 任务类型 | 默认工作流 | 验证方式 |
|----------|------------|----------|
| 小型文档/脚本 | `fsm-lite` | diff + 目标命令 |
| 跨模块功能 | `fsm-10-stage` | 单元 + 集成 + 文档 |
| Bug 排查 | `debugging-workflow` | 复现 + 根因 + 回归 |
| 发布/安全/生产 | `fsm-audit-gate` | 审计证据 + gate 记录 |

## 6. 测试必检

必须存在或明确不适用:

- `TEST_SCENARIOS.md`: 变更路径到测试集合的映射。
- `scripts/pre_test_safety_check.ps1`: 测试前安全门。
- 后端测试命令: pytest/unittest/cargo test 等项目限定命令。
- 前端测试命令: unit、typecheck、lint、Playwright/Vitest。
- E2E 登录路径: 不得手写 token/localStorage/sessionStorage 伪造页面态，优先使用真实 UI 登录或项目登录 fixture。

测试执行原则:

- 不做无差别全量测试；按 diff 选最小必要集合。
- 容器项目先确认容器、镜像、ENV、数据库和挂载。
- 健康检查和 HTTP 200 只是辅助证据，不等于业务验证完成。

## 8. Git 必检

必须核对:

- `git status --short --branch`: 当前分支、ahead/behind、未提交文件。
- `git remote -v`: GitHub remote 使用 `git@github.com:<owner>/<repo>.git`。
- 提交范围: 不混入用户已有业务改动。
- 分支策略: 当前项目是否使用 `main`、`vNNN`、`codex/*` 或项目自定义分支。
- 推送路线: 机器级 SSH 配置处理代理，不在项目 remote 写临时 `pushurl`。

提交前必须运行:

```powershell
git status --short --branch
git diff --check
```

| 项 | 建议位置 | 规则 |
|----|----------|------|
| 标准根 | `CODEX_STANDARD_ROOT`、`project-preset.json.sync.source` | 当前标准源为 `X:/workspace/AIStandard/codex_standard` |
| 个人偏好 | `codex_standard/personal.json` | 不写密钥，不写生产凭证 |
| 端口偏好 | `codex_standard/port-registry.json` | 由 sync-engine 管理 |

| GitHub SSH | 用户级 `.ssh/config` | 项目只记录 canonical remote |
