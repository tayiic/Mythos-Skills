# 长任务交付效率：短任务包、有界检索、证据复用

只在长任务、恢复接续、重复读取或重复验证时使用；小任务保持局部和简短。项目现有权限、唯一验证入口、冻结设施和最终 Gate 是执行边界。

## 一个工作批次

使用现有任务文档与一份证据账本，列出本批目标、受影响文件、事实及证据位置、未决问题、必要测试原子、有效绿证据和停止条件。相关实现、断言、夹具与文档形成依赖完整的批次，再通过项目批准的控制器验证；既有窄范围 TDD 仍可沿用。

续接先恢复原账本的最新短任务包，默认约12行：目标/验收、范围/新增要求、拥有路径、候选/冻结时点、最多3个证据锚点、显式历史摘要、改变的依赖、已绿/失败/缺失、未完成工作、首失败/阻断、下一允许动作、停止条件。必要合同不因行数删除。完成批次、真实阻断或范围改变时更新；正常轮询不另写报告。

## 输入和交接

先定位文件，再限定关键词/符号匹配，最后读取必要行段或 diff。搜索缺失、证据矛盾和未知依赖必须扩大范围。保留原始文件和日志；短摘要不能替代合同原文、失败物证或安全检查。交接只给变化事实、证据、失效原子和下一步，引用同一账本。

需要技能时可按需使用 bounded-task-delivery。本机全局 Codex skill 与项目版本按项目适用性选择；本文本身也提供流程，不依赖额外 MCP。Agent 委派服从用户及项目授权，仅拆真正独立工作。

## 测试去重

按 [TEST_EXECUTION_ORCHESTRATION.md](TEST_EXECUTION_ORCHESTRATION.md) 恢复依赖有效的 LOCKED_GREEN。源码、共享依赖、夹具、测试合同或环境实际失效才构成重跑理由；换任务、换 Agent、无关文档变化或新 commit 不构成理由。

若批准入口没有合法原子续跑能力，按项目规则报告入口能力缺口；规则或 skill 安装不能冒充原子组合实现。复用不能把历史部分 PASS 变成当前完整 Gate。

执行前在原账本记录最小必要 Profile/模式、显式证据来源、RUN/REUSE及理由、首失败及修复/运行态变化证据。有正式计划模式时先生成并审查计划；没有时使用项目既有合法流程，不移植别处参数。出现“无批准的既往PASS来源”时，先补合法来源或确认实际缺失/失效/明确复现要求。结构缺口和总控校验失败必须解决，不能用文字说明豁免。

历史摘要投影只输出身份/哈希、计数、少量失败边界和缺口，不展开全量日志或嵌套续跑证据；失败、矛盾和未知依赖精确回读原物证。摘要和计划检查工具不得裁决当前依赖有效性、REUSE、执行授权或 Gate。ThsFund 的只读工具依赖其正式摘要格式与目录合同；其他项目需先独立适配，不能直接复制为通用运行器。

首次失败按既有 fail-fast 停止。没有实质变化不得原样重试；同类失败再次出现时核对原因，下一次执行须有具体源码修复、运行态变化或获准的有界复现实验。相同指纹只是线索，不证明环境未变或原因相同。静态检查先于昂贵行为验证的原则通过既有入口执行；调整冻结运行器顺序仍须项目专项授权及验证。

最终 Gate 前一起冻结实现、断言、规则和被合同读取的文档。收尾裁决优先写入项目批准的独立证据位置；若仍需修改被覆盖的文件，记录真实失效并只验证受影响原子。文档实际被测试读取时也是依赖，不得一律排除；宽指纹的缩窄须先审查真实读取闭包，再按设施权限单独实施。

## 实测与推广

同时记录完成质量及 Gate、活跃耗时、非缓存输入及输出 token、使用量记录数、重复读取、执行/复用原子和返工原因。缓存输入与费用分别报告，命令耗时可能重叠且包含于任务耗时；不得把它们直接相加或当作耗时占比。

ThsFund 的三项定向查询在冻结快照上由 agent-retrieval-benchmark.ps1 实测输入文本180,085 B→8,985 B，减少95.01%，11项预设字面事实保留。它仅证明这三项查询的检索输出更短，不证明未知事实完备、模型准确率或整个任务节省95.01% Token/时间。完整任务收益仍需至少三批范围相近的真实开发对照，并保持质量与 Gate。
