## 1. 使用方式与文档关系

1. 每次准备发包时，逐项执行本文件的检查项并填写证据，不得复制上次结果冒充本次证据。
2. 本文件负责“现在还要做什么”；开发及上线记录负责“已经开发、验证和上线了什么”。
3. 生产基线文档记录上一次真实生产版本、镜像、数据库、配置和制品基线。
4. 生产部署手册负责环境特有命令、部署步骤和操作红线。
5. 配置管理文档只维护配置合同，不在本文件登记密钥原值。
6. TODO/技术债文档保留问题的详细分析；本文件只收录影响发包或后续版本安排的事项。
7. 带日期的审计报告是历史快照。快照与当前状态冲突时，以当前代码、
   本文件、开发及上线记录和本次新鲜验收证据为准。

状态只能使用：

- `PASS`：已有本次候选版本的新鲜、可重放证据。
- `PENDING`：尚未执行，不得当作通过。
- `BLOCK`：未关闭前禁止上线。
- `N/A`：经负责人确认本次确实不适用，并记录原因。

## 3. 每次发包前通用检查

### 3.1 候选版本冻结

- [ ] 回填最终分支、提交 SHA、tag、变更范围、负责人和发布时间窗。
- [ ] 工作树干净，候选提交已推送，本地与远端一致。
- [ ] 从上次真实生产基线到候选提交生成差异清单，区分代码、配置、数据库、
      依赖、镜像、静态制品和文档。
- [ ] 确认没有真实密钥、测试数据、临时脚本、未授权依赖或未授权制品变更。
- [ ] 确认所有生成物都能追溯到同一候选提交。
- [ ] 记录当前生产制品、运行状态、配置版本、数据库备份点和回滚负责人。

### 3.2 测试与制品

- [ ] 运行项目规定的测试前安全门，失败立即停止。
- [ ] 先映射改动链路与测试场景，再运行最小充分测试集合。
- [ ] 静态检查、单元/逻辑、集成/API、E2E 和运行态证据按改动风险逐层执行。
- [ ] 健康口或 HTTP 200 只作为辅助证据，不代替业务、事故条件和日志验证。
- [ ] 浏览器验证记录 console error、network error、失败请求和视觉异常。
- [ ] 数据库、队列、文件、缓存等副作用均有正向、失败和回滚/清理证据。
- [ ] 构建与打包使用项目固定入口，记录命令、耗时、产物路径和 SHA256。
- [ ] 形成四件套证据：改动链路、执行命令、事故对位、结果。

### 3.3 安全与供应链

- [ ] 依赖和 lockfile 变更经过批准并完成供应链审计；无变更则明确记录。
- [ ] 镜像、基础镜像和运行时变更经过批准；禁止临场拉取或替换。
- [ ] vendor、生成代码、迁移和 CI 配置没有越权改动。
- [ ] 敏感配置通过受控渠道注入，不进入 Git、文档、日志、截图或命令历史。
- [ ] 新接口已完成认证、授权、参数边界、速率/资源、错误收敛和故障隔离验证。

### 3.4 发布审批

- [ ] 研发确认候选范围、开发证据和已知残留。
- [ ] 测试确认生产测试环境验收。
- [ ] 数据库负责人确认迁移、备份、执行窗口和失败处置。
- [ ] 安全或接口负责人确认外部授权域、密钥和脱敏证据。
- [ ] 运维确认部署步骤、观察阈值和回滚步骤。
- [ ] 所有 `BLOCK` 已关闭；未关闭项不得默认带病上线。

## 4. 本次发包专项动作

### 4.1 数据库迁移

无数据库变更时填写 `N/A` 和差异证据；有变更时固定执行：

- [ ] 记录目标环境、数据库名、当前 schema/version 和对象清单。
- [ ] 先在生产测试环境完整演练同一迁移脚本。
- [ ] 在生产执行只读检测或 dry-run，确认当前版本和待执行迁移。
- [ ] 创建可恢复的备份点，并由数据库负责人确认。
- [ ] 仅使用仓库登记的迁移工具显式 apply，禁止临场手工改表或跳版本。
- [ ] 再次只读检测，确认版本、表/索引/约束、幂等性和对象数量符合合同。
- [ ] 确认未触及范围外 schema、表或业务数据。
- [ ] 用受控测试数据验证应用读写、事务、审计和失败回滚。
- [ ] 清理或登记测试数据，保存迁移前后和业务证据。

迁移失败时立即停止应用发布。破坏性回滚只能由数据库负责人按已批准方案执行。

### 4.2 对外或服务间独立授权接口

每个接口逐项登记：

| 项目 | 接口 A | 接口 B/其他 |
|---|---|---|
| 路径和用途 | 待回填 | 待回填 |
| 独立授权头/凭据 | 只登记名称，不登记值 | 只登记名称，不登记值 |
| 配置来源和版本 | 待回填 | 待回填 |
| 生产测试环境脚本 | 待回填 | 待回填 |
| 专用测试数据/目标 | 待回填 | 待回填 |
| 负责人 | 待回填 | 待回填 |

生产测试环境必须先完成：

- [ ] 每个接口都有仓库内可审计、默认不打印密钥的验收脚本。
- [ ] 正确凭据和合法参数验证成功业务语义，不只验证 HTTP 200。
- [ ] 缺失/错误凭据验证 401/403，参数错误验证 400 或合同状态。
- [ ] 配置缺失时接口 fail closed，且不影响无关健康口和业务接口。
- [ ] 不同接口的凭据交换使用失败，证明授权域没有串用。
- [ ] 上游拒绝、异常、超时和状态未知均按合同收敛。
- [ ] 消息、邮件、交易或其他有外部副作用的接口只使用专用测试目标和无敏感内容。
- [ ] 同时保留 HTTP/程序结果与外部系统到达或落库证据。
- [ ] 记录环境、候选 SHA、脚本版本、执行人、时间和结果，不记录凭据原值。

缺少任一接口验收脚本或生产测试环境证据时，该接口保持 `BLOCK`。

### 4.3 生产测试环境常规回归

- [ ] 真实登录、身份、角色和关键权限。
- [ ] 前端静态入口、主要路由、刷新和资源加载。
- [ ] 本次新增或修改的核心业务链路。
- [ ] 数据库迁移后的读写、事务、审计和清理。
- [ ] 外部或服务间接口的独立授权与故障隔离。
- [ ] 至少一个与本次改动无关的核心业务接口，证明没有扩大影响面。
- [ ] 应用日志、浏览器 console、网络请求、数据库和后台任务无新增异常。
- [ ] 性能、超时和资源占用没有超过发布单中登记的观察阈值。

## 5. 上线执行、观察与回滚

### 5.1 上线执行

- [ ] 数据库、配置等前置动作先完成并签收，再发布应用制品。
- [ ] 使用冻结的部署流程，不临时改变镜像、容器、端口、挂载或网络。
- [ ] 确认敏感配置已在进程启动前注入，权限、编码和所有者符合合同。
- [ ] 发布后记录实际提交、tag、制品哈希、配置版本、数据库版本和启动时间。

### 5.2 观察

- [ ] 健康口正常，但继续完成真实业务冒烟。
- [ ] 观察应用 ERROR、HTTP 5xx、超时、数据库错误、后台任务和静态资源失败。
- [ ] 有外部副作用的冒烟只执行批准次数，避免重复消息、交易或写入。
- [ ] 达到约定观察时长且无越线指标后，才能宣布发布完成。

### 5.3 回滚

- [ ] 代码和静态制品可回到发布前记录的提交与制品。
- [ ] 配置可回到发布前版本，回滚过程不暴露敏感值。
- [ ] 数据库回滚方式已明确；不可逆迁移必须有前向修复或备份恢复方案。
- [ ] 回滚后重新验证健康口、登录、核心业务、静态资源和故障隔离。
