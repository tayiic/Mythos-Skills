# mythos-skills 验证与调试手册

> 最后更新: 2026-08-30

## 一、快速验证

### 1.1 后端健康检查

```powershell
curl http://localhost:8000/api/health
```

期望返回: `{"status": "ok"}`

### 1.2 前端访问

```powershell
curl http://localhost:3000
```

期望返回: HTTP 200 + HTML 页面

### 1.3 数据库连接

```powershell
docker exec mythos-skills python -c "from app.core.db import engine; conn = engine.connect(); print('OK'); conn.close()"
```

### 1.4 容器状态

```powershell
docker ps --filter name=mythos-skills --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
```

## 二、日志查看

### 2.1 容器日志

## 三、调试技巧

### 3.1 进入容器交互式调试

```powershell
docker exec -it mythos-skills bash
```

进入后可用工具:
- `python -m app.some_module` — 运行特定模块
- `python -c "..."` — 执行 Python 代码
- `env` — 查看环境变量
- `ps aux` — 查看进程
- `netstat -tlnp` — 查看端口
- `curl localhost:8000/api/health` — 测试 API

### 3.2 代码热更新问题

```powershell
# 确认 bind mount 生效
docker inspect mythos-skills --format '{{json .Mounts}}' | python -m json.tool

# 如果代码未同步，重启容器
docker restart mythos-skills
```

### 3.3 数据库调试

```powershell
# 进入容器操作数据库
docker exec -it mythos-skills bash
psql -h localhost -U postgres -d mythos-skills

# 查看表结构
\dt
# 查看指定表
\d table_name
```

### 3.4 前端调试

```powershell
cd frontend
# 开发模式（含 HMR）
pnpm dev

# 构建并预览
pnpm build && pnpm preview
```

### 3.5 Codex 工作区 sandbox 初始化失败（Windows）

**适用症状**：内置补丁工具在读取目标文件之前即失败，并包含
`windows sandbox` 与 `setup refresh had errors`。这不是业务代码失败，
也不等同于用户未授权。

先以只读证据区分问题边界：确认目标路径存在、文件不是只读、运行主体对文件有
Modify 权限；再检查提升后的只读命令能否读取同一文件。若这些检查通过而内置补丁
工具仍在预读取阶段失败，应将问题记录为 Codex sandbox helper 初始化故障；不得将
未落盘的补丁说成完成，也不得用任意 shell 重写绕过受控补丁链路。

恢复顺序：

1. 保留原始错误文本与未修改的 Git diff；优先重新建立工作区/任务 sandbox。
2. 仅当错误精确命中上述“预读取失败”边界，且本机已安装受控 Codex CLI 时，可使用其
   `--codex-run-as-apply-patch` patch-only 模式作为 Windows 宿主回退。先用
   `Get-Command codex -All` 确认实际入口；若 WindowsApps shim 指向受保护的
   `codex.exe`，使用已核实的用户级 npm `codex.ps1` 包装器，而不是改用任意文件写入命令。
3. 回退调用必须传入完整 UTF-8 patch，且每次成功后立即执行精确 `git diff` 与
   `git diff --check`；随后仍按项目既有测试总控验证。
4. patch-only 回退不可用或仍失败时，停止重试并将原始错误提交至 Codex 支持。不要通过
   关闭 sandbox、放宽项目目录或修改权限来掩盖问题。

> 说明：官方 Codex 文档确认权限与 sandbox 为独立控制面，但未公开
> `setup refresh had errors` 的专用修复。本节是已验证的本机 Windows 恢复流程，
> 不是对该内部错误的官方根因声明。

## 四、常见问题

### Q: 容器启动后立即退出
A: 检查日志 `docker logs mythos-skills`，常见原因:
- 端口冲突
- 数据库连接失败
- 环境变量缺失

### Q: 前端页面空白
A: 检查:
1. 后端 API 是否正常: `curl http://localhost:8000/api/health`
2. 浏览器控制台是否有 CORS 错误
3. Vite 代理配置是否正确

### Q: 数据库迁移失败
A: 
```powershell
# 查看当前迁移状态
docker exec mythos-skills alembic current
# 查看迁移历史
docker exec mythos-skills alembic history
```
